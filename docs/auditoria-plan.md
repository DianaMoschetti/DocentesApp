Conventions: replaced code commented with `// [Diana desde v4.0 OBSOLETO]` / `@* … *@`, keep comments, Bootstrap only, keep encoding/line endings, migration generated but NOT applied, no commit, don't touch `.claude/settings.json`.

## Context
The app needs a change history of every create/update/delete (docentes, designaciones, cargos, actividades, catalogs, users), visible only to the Administrador, with who/when/what (old → new). Today the audit columns exist on a few entities but nothing fills them, and some write paths would produce wrong, noisy or invisible history.

## Decisions (confirmed)
- Existing rows: **leave unknown** (CreatedDate `0001-01-01`, CreatedBy NULL = before auditing; UI shows "—"). No backfill.
- Actividades: **sync by Id**. FKs/enums: **raw values stored, names resolved when reading**; each row also stores a snapshot description of the changed entity.
- All CUD audited; UTC in DB, Argentina time in UI; no logins; "Sistema" without user; EsAdministrador only; PasswordHash/SecurityStamp/ConcurrencyStamp never stored.

## 2. Data model
- **`IAuditable`** (Domain/Base): the 4 audit props. `BaseDomainModel` implements it; `ApplicationUser` implements it directly. Add `BaseDomainModel` to CargoDesignacion, Actividad, Asignatura, Curso, PuntosPorCargo, DocenteUdb, **Dedicacion** (live path, see §1). CreatedBy/ModifiedBy = **userId** or `"Sistema"`; dates UTC.
- **`HistorialCambio`** (one row per changed entity, table `HistorialCambios`): Id long · FechaUtc datetime2 · **OperacionId** Guid · UsuarioId nvarchar(450) null (null = Sistema; same length as AspNetUsers.Id, no FK) · UsuarioNombre nvarchar(256) **null** (snapshot; null on "Sistema" rows, which have no user, and if the token has no name) · UsuarioEmail nvarchar(256) null (snapshot) · Entidad nvarchar(100) · EntidadId nvarchar(200) (text; composite "DocenteId=1;UdbId=2"; headroom for future composite keys, still small enough for the `(Entidad, EntidadId)` index) · EntidadDescripcion nvarchar(500) null (snapshot; same length as the `Observaciones` columns) · Accion (`AccionAuditoria`: Alta=1, Modificacion=2, Baja=3) · DocenteId int null · DesignacionId int null.
- **`HistorialCambioDetalle`** (table `HistorialCambioDetalles`): Id long · HistorialCambioId (FK cascade) · Propiedad nvarchar(100) · ValorAnterior nvarchar(max) null · ValorNuevo nvarchar(max) null (invariant serialization; password events: Propiedad "Contraseña", both null).
- **Seed (Stage 2 result):** the migration includes 6 `UpdateData` calls for the PuntosPorCargo HasData rows. EF 9 always emits them when it adds a column to a table with seed rows, without comparing values (`MigrationsModelDiffer.DiffData`). They only set 0001-01-01 / NULL, the same values the `AddColumn` default already writes, so they change nothing. Accepted as is.
- **Indexes:** `(FechaUtc DESC)`, `(DocenteId, FechaUtc)`, `(DesignacionId, FechaUtc)`, `(Entidad, EntidadId)`, `(UsuarioId, FechaUtc)`, detail FK. No FKs from HistorialCambio to business tables.

## 3. Interceptor, current user, events (revisado)
- **`ICurrentUserService`** (Application/Interfaces) → `CurrentUserService` (API) with `IHttpContextAccessor`: claims `userId`, email, new **`nombre`** claim from `TokenService` (fallback `userName`). Null outside a request (seed) → "Sistema". Claim-based: no DB lookup (no DbContext ↔ interceptor DI cycle).
- **`ContextoOperacionAuditoria`** (scoped, Data): holds the current `OperacionId` and the transaction it belongs to. **With an ambient transaction, every SaveChanges and every explicit event inside it reuses the same OperacionId** (e.g. create user + add role + role event = one operation); without one, one OperacionId per SaveChanges.
- **`AuditoriaInterceptor : SaveChangesInterceptor`** (Data/Auditoria), scoped, registered with `AddDbContext((sp, o) => o.UseSqlServer(...).AddInterceptors(sp.GetRequiredService<AuditoriaInterceptor>()))` and the same in `CustomWebApplicationFactory`. **Overrides both sync and async**: `SavingChanges`/`SavingChangesAsync`, `SavedChanges`/`SavedChangesAsync`, `SaveChangesFailed`/`SaveChangesFailedAsync` (shared private logic).
  - **SavingChanges:** DetectChanges; skip HistorialCambio*, IdentityUserRole/roles/claims/tokens. Changed props = **original vs current value comparison** (not `IsModified`); Modified with no real change → no row and Modified* untouched. Ignored props (Added, Modified and Deleted): the 4 audit columns + the ApplicationUser technical fields. Fill IAuditable (Added → Created*+Modified*; real Modified → Modified*, Created* forced unmodified). Capture details for Modified/Deleted now. **Resolve DocenteId/DesignacionId for Modified and Deleted entries now (before the save)**, from original values and tracked principals, falling back to a DB query (principals still exist at this point). Added entries are kept for SavedChanges.
  - **Transaction:** no current transaction → the interceptor opens one (owned; checks the execution strategy, see §1); with a current transaction → joins it.
  - **SavedChanges:** builds Alta rows (Ids now known), resolves their DocenteId/DesignacionId (principals now persisted), adds the history rows, SaveChanges again (re-entrancy guarded, the inner save only contains HistorialCambio*), then **commits and disposes the owned transaction**.
  - **SaveChangesFailed:** **rolls back and disposes** the owned transaction; clears pending state. If the history save itself fails, the exception propagates and the owned transaction is rolled back → **the business change is rolled back too** (tested).
- **Extensible linking (revisado #12):** `Data/Auditoria/ReglasAuditoria.cs` — a single registry `Type → ReglaAuditoria { Entidad label key, Descripcion(entity), VinculoAsync(VinculoContexto) → (DocenteId?, DesignacionId?) }`. `VinculoContexto` exposes the entry's (current or original) values and cached helpers `DocenteDeDesignacionAsync(designacionId)` and `DesignacionDeCargoAsync(cargoId)` (tracked first, DB fallback, cached per save). Rules: Docente → (Id, –); Designacion → (DocenteId, Id); CargoDesignacion → (docente of DesignacionId, DesignacionId); Actividad → via CargoDesignacionId; DocenteUdb → (DocenteId, –); catalogs/users → (–, –). **Future Resoluciones/Movimientos = one new entry in this registry** (e.g. Movimiento → its DesignacionId → same helpers); unregistered types are still audited, just unlinked.
- **`IAuditoriaEventos`** (Data) **persists its own row**: `RegistrarAsync(...)` adds the HistorialCambio and calls `SaveChangesAsync` immediately, inside the caller's current transaction (same OperacionId); the interceptor ignores HistorialCambio entries so this save doesn't audit itself. Used by UsuarioService: role change (and initial role on create), admin password reset, own password change (`CambiarMiPasswordAsync`, reached from `AuthController.CambiarMiPassword`). ResetPassword and CambiarMiPassword get wrapped in a transaction so password + event commit together.

## 4. API (read side) (revisado)
- `Shared/DTOs/Auditoria`: `HistorialCambioDto` (+ `List<HistorialCambioDetalleDto>` {Propiedad label, Anterior, Nuevo}), `PaginaDto<T>` {Items, Total, Pagina, TamanioPagina}. **(revisado en 6)** The endpoints return the concrete `PaginaHistorialCambioDto : PaginaDto<HistorialCambioDto>`: the generic type appears in swagger as `HistorialCambioDtoPaginaDto`, a type that doesn't exist in Shared, and the NSwag client (`generateDtoTypes: false`) didn't compile. `HistorialCambioDto` carries `FechaUtc` and `FechaArgentina` (Kind Unspecified: sent without an offset, shown as-is by Blazor).

- `API/Controllers/AuditoriaController.cs`, class `[Authorize(Policy = Politicas.EsAdministrador)]`:
  - `GET api/auditoria?usuarioId=&desde=&hasta=&entidad=&accion=&pagina=1&tamanioPagina=50` — `usuarioId=sistema` = rows without user; `desde`/`hasta` are **Argentina dates, `hasta` inclusive** → UTC filter `FechaUtc >= start(desde)` and `< start(hasta + 1 day)` in Argentina time converted to UTC; **`pagina >= 1`** (else 400), **`tamanioPagina` 1..200** (above 200 capped to 200; < 1 → 400).
  - **(revisado en 6)** `GET api/auditoria/historial-docente/{docenteId}`, `GET api/auditoria/historial-designacion/{designacionId}` (same paging rules) → NSwag `HistorialDocenteAsync` / `HistorialDesignacionAsync`. They were `docente/{id}` and `designacion/{id}`, but NSwag names methods by the last path segment: `DocenteAsync` already belonged to `api/designaciones/docente/{id}`, and adding the new route renamed it (and the reports one).
  - `GET api/auditoria/entidades` (labels for the filter combo).
- `Shared/ZonaHorariaArgentina`: **(revisado al cierre)** fixed offset UTC-3 (`Offset`), no `TimeZoneInfo`/IANA lookup: the system always runs in Argentina, which has no DST since 2009 (if that ever changes, this class is the only place to update). The DB keeps UTC. `DesdeUtc` → Argentina time with Kind Unspecified (`FechaArgentina` travels without an offset; Blazor shows it as received); `InicioDelDiaUtc` → 00:00 of an Argentina day in UTC (03:00 UTC), used by the `desde`/`hasta` filters. Used by the API only; Blazor doesn't convert dates.
